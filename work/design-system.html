Case study 04

Keeping the design system and the code the same thing

Role
Translate the Figma design system into front-end components and keep design and code consistent
Team
Size not recorded; a brand approver signs off on brand decisions
Timeline
2026, ongoing
State
First token version implemented in the dev environment and Storybook
Tools
Figma · Storybook and Code Connect · CSS custom properties · React

If I could keep only one part of my job, it'd be this one. Keeping the Figma system and the code the same thing isn't glamorous, but it's what makes everything else move faster, and it's where I've learned the most about how design decisions actually survive contact with a codebase. A UI library in Unity or Unreal has the same problem: one source of truth, or two versions of the design.

Problem

Prototypes drift. A mockup with a hand-picked blue looks right in review, then has to be rebuilt on the real components, where it looks different, and designers and engineers end up arguing about which version is the design.

What I did

  • Worked on a two-layer token system, primitives to semantics, exported to Figma and to CSS custom properties. Components reference semantic tokens only, so a theme change touches one layer.
  • Wrote guideline floors engineers actually use: color pairings with measured contrast, 14px minimum for functional text, 16px for inputs so iOS doesn't zoom, focus rings as outlines so they survive high-contrast mode.
  • Linked icons between Figma and Storybook with Code Connect.
  • Rebuilt approved prototypes on the product's real component CSS and markup, with a check that fails on any raw hex or undefined variable, so "matches the product" is verified rather than claimed.

Token excerpt

/* Tier 1: primitives. Private; only the semantic tier references them. */
--p-color-neutral-0: #FFFFFF;
--p-color-neutral-500: #64748B;
--p-color-navy-800: #0A2E52;

/* Tier 2: semantic. The only tier components use. */
--bg-surface: var(--p-color-neutral-0);
--bg-inverse-neutral: var(--p-color-neutral-900);

/* A component never sees a hex. */
.panel-header {
  background: var(--bg-surface);
  border-bottom: var(--border-width-1) solid var(--border-default);
}

Abridged from the generated token block in one of the prototypes.

Result

The first token version is implemented in the dev environment and Storybook. The tasks prototype runs on the product's CSS and matched the real components' markup state for state.

What I'd change: run the alignment check in CI instead of by hand, so nobody has to remember to.
